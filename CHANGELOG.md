## [Unreleased]

### Changed
- `planning/TODO.md` opens with the frozen-record marker `<!-- praetor: frozen-record; open-work: forge; adr: 0025 -->` and a note that `planning/routing.json` records the done steps and issues #46 and #47 carry the two open ones. The Praetor plan-doc scan read its 22 unchecked boxes as open work although ADR-0025 froze the graph; the boxes stay unchanged (`docs/tools/planning-graph.md`).
- The HISS-11 exception for `.github/workflows/release-matrix.yml` names its category (A, the 90-day interval stated in the entry) and its entry date 2026-10-11 in `.standards.yaml`; the expiry 2027-01-09 is unchanged, and the engine refuses a category whose interval does not give that expiry (`docs/community/security.md`).
- Renovate: `renovate.json` extends the family preset `github>plurano/horistes` instead of `config:recommended`; the preset carries the dependency dashboard, sign-off, the 3-day minimum release age and the no-automerge default, so the file keeps only rules specific to this repository (labels, schedule, groups, the `versions.json` managers). The local automerge rule for minor and patch updates is dropped in favour of the preset default. `renovate-config-validator --strict` (renovate 44.167.4) passes and refuses a planted unknown key.
- Manifest validation in Go (`pkg/manifest`): `manifest.Load` embeds `versions.schema.json` via root package `schema.go` and validates `versions.json` against the Draft 2020-12 schema using `github.com/google/jsonschema-go` before evaluating semantic invariants.
- Manifest schema tests (`pkg/manifest/manifest_test.go`): each planted schema error now asserts the schema path and keyword the validator reports (for a removed nested `drivers.intel.k8s_plugin`: `validating /properties/drivers/properties/intel: required: missing properties: ["k8s_plugin"]`) instead of the `manifest: schema` prefix alone, so an error raised for the wrong property no longer passes.
- Cloud-init generator: `pkg/cloudinit` serializes user-data and meta-data from typed structs with the `go.yaml.in/yaml/v3` encoder instead of concatenated strings, a second barrier behind the allow-lists; keys and values are unchanged, scalars are quoted only where YAML 1.1 would read them as another type (`docs/tools/cli-mcp.md`).

### Fixed

- Kubernetes image precache (`packer/provisioners/55-k8s-precache.sh`): replaced hardcoded `${IMG_*:-...}` fallbacks with required parameter expansions (`${IMG_*:?...}`), eliminating duplicate version definitions so updates to `versions.json` no longer break regression guards; `tests/test_regression_guards.py` now resolves image pins directly from `versions.json` via `packer/builds.pkr.hcl` and enforces that no fallback pins remain.
- Renovate pull requests now carry the milestone, kind/area labels and a tracking reference the PR metadata gate requires.
- Config loading duplicate-key refusal: `manifest.Load` in `pkg/manifest/manifest.go` decodes `versions.json` using `encoding/json/v2` so duplicate object member names anywhere in the document are refused instead of silently overwritten, while keeping schema validation in charge of unknown members. `pkg/builder/pins.go` replaces the hand-written token walker with `jsontext`-backed decoding via `encoding/json/v2`, reusing the standard library's duplicate-key refusal under HISS-19 and keeping existing pins validation invariants green.
- OpenSSF Scorecard Vulnerabilities: `osv-scanner.toml` ignores GO-2026-5932 until 2027-02-15 (category D), mirroring the `not_affected` statement of `security/vex/go.openvex.json`, which now names the product and the expiry. OSV matched the whole `golang.org/x/crypto` module, which only `x/crypto/sha3` reaches; `tests/test_osv_ignores.py` holds the two files equal and fails on an expired or over-long ignore (`docs/community/security.md`).
- `required-checks` on `main` waited for the build jobs of a manual `release-matrix.yml` run on the same commit, which run up to 240 min, and was cancelled by its 30 min bound (run 39169372316 on `bf068b6`). The wait step now leaves out only the job names of workflows no push or pull request starts (ADR-0035); `tests/test_required_aggregator.py` derives both sides from the workflow triggers and fails when the filter drops a gate check or a required context.
- `required-checks` counted the time gate checks sat queued for a runner against its 30 min bound. It was cancelled while every gate check later passed (run 39190971221 on #182, run 39182790940 on #181). `tools/ci/wait_gate_checks.py` now replaces `lewagon/wait-on-check-action`: each gate check gets 30 min from its own start, queue time never counts, and the whole wait ends at 120 min of wall clock (ADR-0036). `tests/test_wait_gate_checks.py` runs the script on a simulated clock: a check queued for 40 min and then green passes, and a check that never starts fails at 120 min.
- semgrep job lock: semgrep 1.180.0 and 1.181.0 pin `mcp==1.29.0`, which GHSA-84m7-p3x7-pcfv affects (fixed in 1.30.0; Dependabot alerts 1 and 2). `.github/requirements/sast-overrides.txt` replaces the pin with 1.30.0, the lock header compiles with `--override=` so Renovate recompiles it the same way, and the job installs the lock with `--no-deps`, since pip otherwise refuses the replaced pin. semgrep 1.180.0 runs with mcp 1.30.0 and its canary refuses the planted finding; `tests/test_governance.py` fails when the lock carries an affected mcp, the header omits the override, or the install drops `--no-deps` (`docs/security/supply-chain.md`). Supersedes Renovate PR 177, whose lock downgraded semgrep to 1.136.0.
- `run_preparation` in `tests/test_container_integration.py` ended its timeout path on the `NoReturn` call to `skip_or_fail`, which CodeQL read as an implicit `return None` (alert 34, `py/mixed-returns`); the timeout branch now re-raises after the call, so every exit is explicit. Behaviour is unchanged and stays covered by `tests/test_live_prerequisites.py::test_preparation_beyond_its_bound`.
- K3s flavors: `52-k3s-runtime.sh` disabled the K3s unit behind `systemctl list-unit-files | grep -q`; under `pipefail` the early `grep` exit gave `systemctl` a SIGPIPE (status 141), the condition read false, and every K3s image booted with its unit enabled. `k3s-server-generic` then crash-looped on the netboot overlay root and failed the netboot smoke test (release-matrix run 39140519699). The installer now runs with `INSTALL_K3S_SKIP_ENABLE=true` and the provisioner fails when `systemctl is-enabled` reports the unit enabled; `tests/test_provisioners_execution.py` covers both roles with an enabled and a disabled unit, and all four cases fail against the previous script (`docs/flavors/k3s.md`).
- Release matrix job bounds: `build-matrix` and `sign` had no `timeout-minutes`, so a hung job would run until GitHub's 6 h default. `build-matrix` now stops after 240 min (the slowest measured build job took 152 min, base-nvidia-legacy on 2026-10-18; the slowest successful one 115 min) and `sign` after 30 min; `tests/test_release_matrix_flavor.py` refuses a job without a bound or with one at the 360 min platform default.
- Upstream pins for every flavor: the NVIDIA tiers pinned driver branches the Ubuntu 26.04 archive does not carry (565) or carries only as transitional packages (535 now installs 580, 610 now installs 615), the datacenter tier installed a `615-open` package that does not exist, the CUDA labels named releases with no matching `cuda-compat` package (12.2) or a different driver (12.8 pairs with 570), `appliance-ci-runner` installed `qemu-user-static`, a virtual package with two providers that apt refuses to pick, and `cdebug` had a stale 0.5.1 default in `packer/builds.pkr.hcl`. Pins are now 580/595/615/615 with CUDA 13.0/13.2/13.4/13.4; the datacenter tier installs `nvidia-headless-615-server-open`, `nvidia-utils-615-server` and `nvidia-fabricmanager-615`; the provisioners require each pin from `versions.json` (`${VAR:?}`) instead of falling back to a hard-coded branch; `appliance-ci-runner` installs `qemu-user-binfmt`. `tools/ci/upstream_sources.py` now checks every flavor: release-asset and repository URLs, container image tags in their registries, each NVIDIA tier's packages in the archive (absent or transitional fails), the CUDA label against `cuda-compat` and its driver, apt version pins for Docker CE, kubelet and the NVIDIA Container Toolkit, and every literal `apt-get install` name in the provisioners. `tests/test_upstream_sources.py` plants a fictional pin of each kind and asserts the check fails. The check against the previous pins reported 10 missing sources.
- The AMD ROCm flavors fetched a key name (`rocm.gpg`), releases (`10.0`, `7.14`) and an apt suite (`resolute`) that repo.radeon.com does not publish; `k8s-node-amd` failed with a 404 about 20 minutes into its build (run 39108353867). The pins are now ROCm 7.2.4 and 6.4.4 on the `noble` suite with the documented key and apt pin, the repository root and suite come from `versions.json`, a failed index update fails the provisioner, and a new `release-matrix.yml` step checks every pinned source before Packer starts.
- Release matrix concurrency: every run on a branch shared one concurrency group, which holds one running and one pending run, so manual runs of different flavors cancelled each other. Five rebuilds dispatched on main at 403559e were cancelled this way, the last by the weekly schedule (run 39106005526). A manual run now has a group per flavor; schedule and release runs keep the shared group (`tests/test_release_matrix_flavor.py`).
- Kubernetes image preheat: three pinned images had no registry host (`prom/node-exporter`, `intel/intel-gpu-plugin`, `rocm/k8s-device-plugin`). `ctr` takes the first component as the host and has no `docker.io` default, so the k8s-node-intel build failed on main at d21d8fc (run 39103045700, "lookup intel ... server misbehaving"); k8s-node-amd and every profile that caches node-exporter would fail the same way. - Live container tests: the Docker probe in `tests/test_container_integration.py` gave up after one 5 s `docker info` call, which missed on CI run 39096311247 and failed eight tests with no cause. It now makes up to 3 attempts of 20 s within 60 s, stops at once when the daemon is not reachable, and the skip or failure message names the cause, the attempts and the measured time. `tests/test_docker_probe.py` plants a slow daemon, a daemon that answers on the second call (which the single-shot probe misses), a stopped daemon and a missing CLI; the CI pytest job records the runner's `docker info` answer time in its step summary.
- Pull-request metadata gate: `pr-project-gate.yml` no longer cancels its own runs. Label and milestone events cancelled earlier runs on the same head commit, and the cancelled check suites held pull requests blocked with every required check green; each run now has its own concurrency group.
- Release matrix workflow (#152): `workflow_dispatch` builds the requested flavor selected via the `flavor` choice input instead of being fixed to the 3 generic flavors; scheduled and release runs keep the generic flavors, and unknown flavors fail closed before runner provisioning.
- Aegis build workflow: a failed run keeps `serial.log` and the new `boot-failure.json` (`imago.aegis.boot-failure.v1`, written by `tools/aegis/boot_once.py` when the boot fails) as a three-day run artifact, because run 39075280378 timed out in the boot step and its serial log was lost with the runner (`docs/operations/aegis-build.md`).
